## Issues

- **Label checks.**
  - `label_check` (the "Check the label" note shown at stage_start): followed 0, ignored 23. As in round 3, the ignored cases are mostly folder listings declared as "List files in the document store (attempt 2)" and screening reads declared under a listing or in-depth label.
  - `label_check_end` (the end-of-stage "Label: these calls looked like X" note), following the coordinator's convention update: followed 7, ignored 5.
    - The followed cases: "List matter folders" was declared right after the note (052_T1, 241_T0, 241_T2, 181_T1), a scan was declared after a path-search stage (003_T1, 241_T1), and "Screen…" was declared after a check stage (052_T0 [139]-[151]).
    - The ignored cases kept "Read a chosen matter's documents in depth", "Check or revise the response" or "Screen…" after the note suggested "Read documents picked from the file listing". In 003 and 241 the note seemed to misfire: the reads were chosen from searches, so the agent's label fits the taxonomy better.
    - 052_T0 [37]-[42] is counted as ignored, but the agent did not keep its old label. It declared a third label ("List files in candidate matters") for the next path-regex work.
  - Most end-of-stage notes (about 20 more) had no later work of the same kind, so they are `none`.
- **Agent names with task content.** Some agent new-stage names contain matter numbers, practice or committee names, a hindsight word ("criteria") or a check.py task word ("clearance"). Their notes use `declared: new: <name with <…> in place of that part>`. The full name is kept in `agent_new`. Affected: 003_T2, 052_T0, 052_T2, 102_T0, 102_T1, 141_T1, 241_T0.
- **Post-processing of saved output.**
  - Stages that only aggregate, rank, diff or filter a scan's saved output were labelled "Scan document text with an extraction script", following the round-3 precedent. They do not unzip documents again. Examples: 003_T1 [27]-[32], 003_T2 [81]-[86], 052_T0 [31]-[36] and [65]-[69], 181_T0 [41]-[45], 181_T2 [136]-[141], 241_T0 [29]-[34], 192_T1 [16]-[21].
  - Batch 2 of this round proposed "NEW: Tally saved search output per matter" for this pattern. If that name is adopted at the merge, these spans should move to it.
  - A printed saved file-name candidate list (052_T2 [147]-[152]) was labelled "Search file names for request keywords".
  - 052_T2 [153]-[160] writes a scratch table of 33 matters with structure and status labels from earlier reads. It does not touch the store. It was labelled "Calculate figures for the answer". Batch 3's proposed "NEW: Tabulate findings across candidate matters" fits it more closely.
- **Splits.** Declared spans that mixed a store-wide or saved-output step with first reads were split at the tool-call boundary, with the same `agent_new` on both parts. Examples: 052_T0 [65]-[69] / [70]-[103], 052_T2 [97]-[103] / [104]-[146], 141_T0 [37]-[41] / [42]-[55], 141_T2 [23]-[27] / [28]-[47], 181_T0 [41]-[45] / [46]-[48], 181_T2 [51]-[55] / [56]-[71], 192_T1 [46]-[50] / [51]-[65], 003_T1 [16]-[20] / [21]-[26]. The `label_check` of the declared span goes on the part where the suggested work was done.
- **Judging from listings or snippets.** When a matter was hit by snippet or metadata scripts but never listed or read, its omission was coded surfaced-not-opened (102_T0, 141_T1, 141_T2). 181_T1 is different: its listing showed the needed conflicts documents, and the agent dismissed all 43 listed matters by file name. That case is coded listed-document-not-opened, although the agent was only loosely "working on" that matter.
- **181_T0.** Coded over-narrow-filter, but only on indirect evidence. The conflicts matter never appears in any output the agent viewed. The scan's saved hit files almost certainly contain it, because other runs' scans hit it with patent terms, but those files were never printed in full.
- **Rate criteria.** In 141 all three runs stated the rate over the signed deals they had confirmed (26/26, 20/20, 18/18). This is coded incomplete-population at the write stage, separate from the missed matters.
- **review-endorsed** was used twice.
  - 169_T0: the write review told the agent to drop a facility with a post-closing mortgage if the mortgage was core. The agent dropped it, and the next review called that a possible over-removal.
  - 241_T2: the screening review said a needed matter's committee direction rested on a draft report. The answer then moved that matter out of the strict count. This one is weaker evidence that the review caused the change.
- **169 split.** In 169 (mixed: T1 passes) the split is at the write stage, on how broadly the real-estate carve-out was read. No new stage or label note played a role.
- **Refused calls.** Calls refused by the stage protocol are tagged `tool error`. A refused read, edit or bash call outside any stage was placed in the next stage, and a refused stage_start in the open stage. "Stage check" warnings were not tagged.
