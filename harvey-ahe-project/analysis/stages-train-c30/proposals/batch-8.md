## Issues

- **How I applied label_check.** A stage is `ignored` when I relabelled the declared span to one of the stages the "Check the label" note suggested (with `declared:` in the note). It is `none` when the declared label fits the dominant work, including mixed spans whose minor part matched a suggestion (e.g. a whole-store glob run in parallel with a capped folder listing under "List files in the document store"), and when I relabelled to a stage the note did not suggest. No stage in this batch was `followed`: no agent closed a stage right after the note and opened the suggested one. Counts: 32 ignored, 0 followed across 24 runs. The most common ignored notes: "List files in the document store" (attempts 2-3) that were per-matter counts (List matter folders), and "Read documents picked from the file listing" or "Read a chosen matter's documents in depth" used for screening reads.
- **Stage-protocol warnings that are not refusals.** Some results carry "[Stage protocol] Stage check: this call looks like ..., which does not match the open stage" (017_T0 [49], 017_T1 [44], 068_T1 [29]). The call still ran, so I did not tag `tool error`. I only noted them in the stage note.
- **Named-list scans.** I relabelled declared extraction scans over a short named list of candidate matters (5-9) to "Search within a candidate matter's files" (181_T1 [36]-[41], 247_T0 [14]-[21], 247_T1 [26]-[31]). I kept "Scan document text with an extraction script" for a 24-matter hand-picked list (141_T0 [24]-[31]) and for scans over number ranges. Where to draw this line is a judgement call.
- **Hindsight for count tasks (017).** No value fits an answer that names every rubric matter but has the wrong rate because of the population or an add-back flag. I followed round 1 and used `answer misses target` when a population member was left out (017_T1) and `answer over-inclusive` when extra deals were counted (017_T0, 017_T2).
- **Tasks with no rubric matter numbers (181).** Hindsight treats the four associate-bearing litigation matters and the conflicts matter that names the fifth associate as the targets, as batch 8 did in round 2.
- **review-endorsed (240_T0).** The review after the file-name search told the agent to rank candidates by matter number and check from newest to oldest. The agent did, and never opened the low-numbered matter it needed. Later reviews flagged the ranking by number, mostly naming higher-numbered matters. I recorded `review-endorsed` and not `flagged-ignored`, because the review set the decision.
- **Specific flags that were ignored.** Several runs failed exactly where a review named the cause: 141_T2 [35] named contribution agreements as dropped by the agreement-name filter, 240_T1 [36] named the needed matter's tax folders, 240_T1 [55] named the matter-number cutoff, and 247_T0 [45] said no disclosure document of the picked matter had been read. In the passing runs the critic changed the outcome three times: 093_T0 (the write review named the shorter settlement term, and the answer was fixed), 198_T0 (swapped matter numbers after parallel reads), and 198_T2 (an appraisal-only inclusion removed after three reviews). In 198_T1 the agent read further and kept an exclusion that a review had questioned.
- **Whole-store file dumps without overflow.** 068_T0 [10]-[11], 141_T2 [10]-[11] and 247_T0 [10]-[11] printed 700-800K characters, and the runs continued. They are tagged `huge output` with no overflow. In 247_T0, that dump was the only place the needed cover letter appeared, so I used `listed-document-not-opened` (merge convention 5: the document was shown in the agent's own output). The agent never listed the matter it picked.
- **Truncated own listings.** In 240_T1 [37]-[42], the 14-matter listing printed only the first 260 of 838 lines, so the needed matter, listed last, was never shown. The next listing skipped matters below a number cutoff. I put the error on the cutoff stage as `surfaced-not-opened`.
