# Batch 3 proposals (tasks 011 014 016 017 035 046; all 18 runs failed)

No new stages, tags or hindsight values were needed. Every run fit the frozen stage vocabulary. Four new error kinds are proposed.

| Kind | Name | Definition | Example | Why no existing name fits |
|---|---|---|---|---|
| error kind | NEW: over-exclusion | The agent read or scanned a needed matter but judged it outside the request (through a narrow or literal reading of a qualifier or exclusion, or with no stated reason), so the answer leaves it out | 016_T0 [35]-[36] (two financings excluded as real-estate-secured); also 016_T1, 016_T2, 011_T0 [62]-[63], 046_T1 [52]-[53] | over-inclusion is the opposite direction. surfaced-not-opened needs the matter never to have been opened. hedged-answer is about qualifying the conclusion, not dropping an item. |
| error kind | NEW: misattributed-matter | The agent read the needed matter's documents, but the answer attributes them to a different matter number: an engagement number printed inside the documents, or the number of another matter read in the same parallel batch | 014_T2 [34]-[35], 035_T0 [44]-[45] | missing-identifier covers an answer that omits the number. Here a different, non-qualifying number is stated. The hindsight value "answer wrong matter" exists, but no error kind matches it. |
| error kind | NEW: incomplete-population | A count or rate answer rests on a deal set that leaves out members of the population the request covers (for example, the denominator of a rate), even though every rubric-named matter is present | 017_T0 [20]-[27] | The rubric names only the matters with add-backs, so the missing denominator deals cannot be shown to have surfaced or been missed. That rules out surfaced-not-opened and search-miss. |
| error kind | NEW: misclassification | The answer includes a needed matter but puts it in the wrong bucket or category the request asks for (for example, sponsor vs corporate) | 017_T1 [59]-[60] | over-inclusion asserts that a non-qualifying matter qualifies. Here the matter qualifies and is named, but it is put in the wrong bucket. |

## Issues

- Engagement numbers printed inside documents can differ from the matter-folder number. In 014_T2 the answer cites the in-document number. In 011_T0 [23] the agent searched for a folder with that number and found an unrelated matter. This may recur wherever a client has several matters.
- In 035_T0, results of parallel reads appear in the log in a different order from the calls. The raw trace pairs them by call id. The misattribution there (one issuer's agreement cited under another matter's number) may come from mixing up results within a parallel batch, but that cannot be confirmed from the agent's text.
- Batch-2's empty-grep issue extends further. Grep-tool calls limited to `.docx` returned nothing even with `**/` globs. Examples: 016_T2 [26]-[34], eight per-matter greps with `**/*.docx` over matters whose agreements contain the words; 046_T1 [27], `**/*prospectus*.docx`. The grep tool appears not to read docx text at all, so only `.eml` and other plain-text files ever produce hits.
- Task 016's rubric counts financings that the request's real-estate and project exclusions could plausibly cover (a hotel term loan with mortgages, a data-centre loan, a draft REIT mortgage loan). "NEW: over-exclusion" records the hindsight mismatch without judging the agent's reading as unreasonable.
- Task 017's rubric does not name the two sponsor deals without add-backs. For 017_T0 the write stage uses "answer misses target" loosely, for a short denominator rather than a missing named matter.
- 014_T1 ended on context_overflow right after its write, so the deliverable was graded. Its last stage is "Write the response" with the tag `run ended: context overflow` and hindsight "answer over-inclusive", not "context overflow".
- Some write stages carry two errors. 016_T0 and 011_T0 have two other_errors on the write stage. In 016_T2 and 035_T0 the first error and a later error are on the same stage, so that md row has both markers. The md files add a `**Later error:**` line per other_error.
- When a failed search led to an answer naming only non-qualifying matters (035_T1, 035_T2, 046_T0), no separate over-inclusion error was recorded, following 104_T1. Over-inclusion was recorded where extra matters were added alongside qualifying ones the agent had found (011_T2, 014_T0, 016_*, 046_T2) or from a draft reading (035_T0).
- 046_T0 [24]-[25] is a store-wide script that keeps only the two listing-top matters. It is labelled "Search within a candidate matter's files" because its scope is those two matters.
- 046_T1 [54]-[59] changed an excluded candidate's matter number to another non-qualifying number after a file-name search for the issuer. This was not recorded as an error because the exclusion had already failed those criteria.
- 017_T1 [8]-[9] and [12]-[15] are store-wide globs over folder-type names (transaction documents, engagement). They are labelled "List files in the document store" with hindsight "none", although the log marks matters as FIRST TIME there.
