## Issues

- 199_T1 has a later error at the document level: a picked matter's listing showed five diligence files, and one was never read or cited. It was given `surfaced-not-opened`, which is defined at the matter level. If document-level omissions recur, a separate kind such as "document-not-opened" may be clearer.
- Globs restricted by a folder type (`**/Transaction Documents/**/*.docx`, `matters/**/Transaction Documents/*`) were labelled "Search file names for request keywords" (194_T2 [21]-[22], 195_T1 [5]-[10]). They match a folder name derived from the request's subject, not request words. A stage such as "List files by folder or document type" could separate them.
- Whole-store glob stages whose listing shows a rubric matter (1046-00001 in task 195) got `target surfaced`, matching other parallel batches (e.g. 243, 241). Under batch-1 usage this would be `none`.
- Content-grep stages whose only hits are `binary noise` were still given `target surfaced` / `target partly surfaced` because the log marker fires. The agent gets no real signal from those hits, so the situation resembles `target in folder list only`.
- 194_T2 [15]-[20] holds one grep and four reads. It was labelled by the grep, not by the count, because the grep set up the next steps and the reads were leftover listing-top memo reads (three of them at nonexistent paths).
- Pattern across tasks 192, 194, 195, 198, 199 and 200: a content grep does not read .docx text. Runs that relied on it found only matters with email or spreadsheet mentions. Runs that wrote a store-wide extraction script either overflowed the context (194_T0, 198_T2: 4.7M and 9.1M chars) or reached every matter (192_T0, 199_T2) and then lost some at a later step.
