## Issues

- **210: hindsight for counting tasks.** The rubric names clients, not matters. I treated a rubric client's number series as the rubric matters. Listings that show all series (full folder list, per-matter engagement-letter list) got "target surfaced", reads of those clients' letters got "target opened", and folder lists were not marked "target in folder list only" because the folder names themselves are the evidence for a count. The log header shows "none named", so there are no FIRST TIME markers to anchor this.
- **"Answer wrong matter" vs "answer over-inclusive" for rankings.** 210_T1 names only non-rubric clients, so I used "answer wrong matter". 210_T0 and T2 mix rubric and non-rubric clients, so I used "answer over-inclusive" (per the batch-2 rule). In 210 the extra clients are a consequence of the miscount, so I recorded no separate over-inclusion error.
- **Over-inclusion from a loosely read qualifier recurs** (the batch-2 issue for 082_T1). 209 T0–T2 named a matter whose deal had closed as "still open", reading the closing-posture allowance loosely. 223_T0, T2 and 230_T1 counted financings or asset purchases as real-estate matters. All are recorded as over-inclusion; in 209 it is an other_error because the needed matter never surfaced. A kind like "misread-qualifier" may be warranted.
- **Searches cut short by the agent's own `head` / `sed -n` caps.** In 209_T1 [22]-[23] and 230_T1 [12]-[13] the needed matters were missed because the agent's command printed only the first 240 lines or hits. I tagged no tag (there is none for this) and used search-miss. A tag such as "output capped by command" would make this visible.
- **Placement of first error when listing reads precede a search.** In 209_T1, 230_T0 and 238_T1 the runs first read listing-top matters, then searched. Following 032_T1, the first error goes on the failing search (search-miss), not on the listing reads, because the agent did search afterwards.
- **211_T1 [13]-[14]** is a store-wide content grep for an amount and deal term taken from a document already read, not from the request. I labelled it "Search file contents for request keywords" with a note, because no stage covers "search for a lead found in a document".
- **238_T2 first-error stage.** The exclusion judgement was made with no further reads after a file listing, so I put the first error on "Write the response" (where the matter was written off), not on the listing stage.
- **Judge leniency.** 223_T0 passed qualifying-matter criteria for 1017-00009, 1026-00004 and 1036-00004 even though its table marks them as lacking an indemnity. This was annotated as graded; it does not affect stage labels.
